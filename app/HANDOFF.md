# Surmount B2C — Front-End Handoff

This repo is a **working Next.js front end**, not a design mockup. It's a high-fidelity, interactive prototype built with production-grade tooling, so the development team can **build directly on top of it** rather than rebuilding the UI from scratch.

- **GitHub:** https://github.com/shawnji33/surmount-b2c

- **Active branch:** `onboarding-flow`
- **Live preview (Vercel):** https://app-ten-bay-85.vercel.app
- **Design reference (Figma):** https://www.figma.com/design/vnL70Jo9LWTOXta9eyJnkO
- **Design-handoff flow map (dev-only page):** `/flows` (also on the Vercel preview)

## 1. Run it locally

The app is in the `app/` subfolder of the repo.

```bash
git clone https://github.com/shawnji33/surmount-b2c.git
cd surmount-b2c/app
npm install        # rebuilds node_modules (not committed)
npm run dev        # http://localhost:3000
```

`node_modules/` and `.next/` are intentionally **not** in the repo — they're regenerated by `npm install` / `npm run dev`. Never commit them.

| Task | Command |
|---|---|
| Dev server (hot reload) | `npm run dev` |
| Type-check (fast pre-commit gate) | `npx tsc --noEmit` |
| Production build (full verification) | `npm run build` |
| Run production build | `npm run start` |

## 2. Tech stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript** (strict)
- **Styling:** Tailwind CSS v4 + **CSS Modules** co-located per component (`Name.module.css`)
- **Icons:** `@phosphor-icons/react`
- **Charts:** `lightweight-charts`, `recharts`

> ⚠️ This is **not** the Next.js most devs know — it's a newer major with breaking changes. See `app/AGENTS.md` and read `node_modules/next/dist/docs/` before assuming older APIs.

## 3. IMPORTANT — what's real vs. what's scaffolding

This is a **prototype**. The UI, flows, interactions, and styling are real and reusable; the data/back end is not.

- **No backend / no auth.** Every screen renders from **mock data or local component state**. Mock data lives in `src/lib/` (e.g. `src/lib/mock-activity.ts`) and `src/hooks/`.
- **Forms don't persist.** e.g. "Contact us" opens a `mailto:`; "Update payment method" routes into the Plaid-style onboarding flow (UI only).
- **Dev-only routes** (remove or gate before production):
  - `/dev` — hand-maintained index of every screen (start here to explore).
  - `/dev/settings-modal` — Settings modal preview (`?tab=`, `?step=`).
  - `/flows` — the design-handoff flow map (composes live screens in iframes).
  - `FigmaCaptureLoader` (in `src/app/layout.tsx`) — injects a Figma capture script only when the URL hash starts with `#figmacapture`; harmless otherwise, can be removed.

**Dev team's job:** wire real APIs/auth, replace mock data with live data, add persistence, and gate/remove the dev routes. The component layer, design system, routing, and flows carry over as-is.

## 4. Screen map (where things live)

- **`/`** → login (`src/components/LoginPage.tsx`)
- **`/onboarding/*`** → ~50 single-step pages: identity/KYC, financial profile, strategy quiz, funding, `connect-brokerage`, `link-bank` (`?mode=update` = update funding source). Shared inputs in `src/app/onboarding/_components/`.
- **`/home`** → investing dashboard (shell: `src/app/home/HomeShell.tsx`, sidebar: `src/components/Sidebar.tsx`). Sub-surfaces: `home/saving`, `home/strategy/[id]`, `home/agents/*`, `home/playground/*`.
- **`/activity`** → activity / orders feed.
- **`/plans`** → **plan management** (pricing page). Query params drive preview states: `?cycle=monthly|yearly`, `?step=downgrade-confirm|scheduled|scheduled-toast|renew-confirm|renewed|upgrade-confirm|upgraded`, `?target=free|core|plus|pro`.
- **Settings modal** (opened from the sidebar account menu): tabs **Billing**, **General**, **Privacy & security**, **Support** (Support includes an in-place FAQ view). Source: `src/components/SettingsModal.tsx` + `src/components/settings/*`.

## 5. Design system & styling rules

- **Tokens:** `src/styles/tokens.css` is **auto-generated from Figma — never hand-edit.** Imported by `src/app/globals.css`. Use `var(--color-*)`, `var(--radius-*)`, `var(--spacing-*)` — no raw hex/px.
- **Shared design system repo:** https://github.com/shawnji33/design-system-surmount (shadcn/Radix components + Storybook). Storybook is deployed at https://shawnji33.github.io. **Note:** this B2C app is *not* a shadcn project — it replicates DS component designs in CSS modules.
- **Core rules:** Geist for body / Inter for display; **sentence case only** (never ALL CAPS); font-weights **400/500 only**; primary CTAs are **dark gray**, not brand blue (brand blue is reserved for intentional callouts like savings badges + charts); use the shared `@/components/Button` for all buttons.
- **Motion:** enter ease-out (~200–300ms), accordions animate `grid-rows 0fr→1fr`, drill-in nav slides in/out, all respect `prefers-reduced-motion`.

## 6. What was built most recently (plan management)

The plan management experience is complete end-to-end and is the best-documented area:

- **Plans page** (`/plans`) — 4 tiers, monthly/yearly toggle with rolling-number animation and struck annualized pricing, upgrade/downgrade/reactivate flows with cost-summary cards.
- **Settings → Billing** — current plan, cost disclosure on reactivate, payment-method **Update** links into the bank-update flow (`/onboarding/link-bank?mode=update`).
- **Settings → Support** — Request a feature (Typeform embed — needs a real form id), Contact us (email form), and an in-place **FAQ** view (25 Q&As, single-open accordions).
- **Flow map** (`/flows`) — visual walkthrough of every plan management flow (upgrade, downgrade, cancel, reactivate, billing cycle), each a live screen.

Open outstanding items: real **Typeform id** for the feature-request embed; some **mock pricing drift** (settings billing invoices show `$20.00` while canonical Plus is `$100/yr`).
